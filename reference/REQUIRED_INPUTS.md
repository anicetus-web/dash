конкретное место конфигурации, указанное в колонке «Куда подставить». Расчётный
модуль, интерфейс и XLSX ничего не знают про Битрикс и не требуют правки.

## Примечания

**1. История стадий.** Код уже устойчив к её отсутствию: если маршрут истории
недоступен для части сущностей (временный сбой), их прежние события сохраняются
из предыдущего успешного снимка — этапы не теряются. Если маршрут отсутствует
целиком, воронка считается по текущей стадии каждой сущности без докраски
пропущенных этапов из истории — числа менее точны, но не падают.

**2. История ответственных.** Это единственное место, где ответ «недоступно»
меняет поведение системы, а не только точность. Спецификация требует засчитывать
этап тому менеджеру, который вёл сущность в момент прохождения (не текущему
ответственному). Если API портала такую историю не отдаёт:

- либо согласовать дополнительное пользовательское поле или автоматизацию,
  фиксирующую ответственного при прохождении стадии, и передать нам его ID;
- либо принять упрощение: весь путь сущности будет отнесён её текущему
  ответственному. Дашборд продолжит работать и явно пометит эти данные
  предупреждением, но фильтр по менеджеру будет неточен при передачах сделок
  между сотрудниками.

**3. Перенос источника в дочернюю сделку.** Дашборд намеренно не угадывает
источник сделки, если он отличается от источника её компании — такое
расхождение означает проблему настройки портала, а не данные для анализа.
При активной интеграции система сама обнаруживает и предупреждает о таком
расхождении (код предупреждения `SOURCE_NOT_INHERITED`), но подтверждение
самого факта переноса аудитом ускорит диагностику на старте.

## Что уже готово принять эти значения

Реализовано и покрыто проверками (`npm test`, файл `scripts/check-bitrix.mjs`):
клиент с таймаутами и повторами, курсорная/смещённая пагинация без молчаливой
обрезки, устойчивая к разным регистрам полей нормализация, дробление больших
периодов на временные окна, деградация без потери здорового снимка, сохранение
истории сущностей с неудавшимся перезапросом. Подстановка значений выше не
требует правки этой логики — только заполнения таблицы.

Переключение источника данных на боевой — переменная окружения `DATA_SOURCE=bitrix`
в `.env` (по умолчанию `demo`).
