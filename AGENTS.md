# 3ДБИЛД — дашборд воронки продаж

Веб-дашборд сквозной воронки продаж через две воронки Битрикс24 («Компании» и «Сделки»)
с режимами Статики и Динамики. Размещается на платформе «Битрикс24 Вайбкод».

## Начать отсюда

1. [`CONTEXT.md`](CONTEXT.md) — глоссарий домена и инварианты расчёта. **Читать до любой работы с расчётным модулем.**
2. [`.scratch/funnel-dashboard/spec.md`](.scratch/funnel-dashboard/spec.md) — источник истины по объёму работ.
3. [`reference/CODE_REUSE_MAP.md`](reference/CODE_REUSE_MAP.md) — что можно брать из референса Altech, а что нельзя.

## Стек

Node.js ≥ 20, ESM, **ноль внешних зависимостей**. Фронтенд — ванильный JS без шага сборки.
Не добавляй зависимости без явного согласования: отсутствие сборки — осознанное решение
ради надёжного деплоя на Вайбкод.

```bash
npm start      # сервер на http://localhost:3000
npm run check  # синтаксическая проверка всех файлов
npm test       # проверки расчётного модуля и хранилища
```

## Вход

Свой логин/пароль, без внешних зависимостей: `node:crypto` (scrypt) для хешей,
`randomBytes`/`randomInt` для токенов и генерации паролей.

- `src/auth/passwords.js` — хеширование, проверка, генерация пароля. Открытый
  пароль не покидает эту границу и не пишется никуда, кроме одноразового
  ответа API сразу после создания/сброса.
- `src/auth/userStore.js` — сотрудники и сессии, **отдельный файл**
  (`data/users.json`, дефолт), НЕ раздел снимка: снимок целиком заменяется
  при каждой синхронизации, и учётные записи стирались бы вместе с ним.
  Запись — тем же `writeAtomic`, что и снимок (`src/storage/jsonStore.js`).
- `src/api/authRoutes.js` — маршруты `/api/auth/*`. Белый список открытых
  путей (`PUBLIC_API` в `src/server.js`) — всё остальное под `/api/` закрыто
  входом до разбора маршрута.
- `public/translit.js` — транслитерация кириллицы и подсказка логина по
  имени. Один файл на браузер и сервер: правила обязаны совпадать до буквы,
  иначе подсказка в поле и сохранённый логин разойдутся.

Роли — `admin` (видит раздел «Сотрудники», может всё) и `employee` (видит
только дашборд). Последнего действующего администратора нельзя ни удалить,
ни отключить, ни разжаловать — иначе управлять доступом стало бы некому.

Вход через сам Битрикс24 (SSO) сейчас не подключён — нет прав администратора
портала, чтобы зарегистрировать там приложение (см.
[`reference/REQUIRED_INPUTS.md`](reference/REQUIRED_INPUTS.md)). Место под
него оставлено: `bitrixUserId` в записи сотрудника и структура маршрутов
позволяют добавить SSO как ЕЩЁ ОДИН способ завести сессию, без переделки
хранилища — по тому же принципу, что и адаптер источника данных (`demo` |
`bitrix` в `src/sync/source.js`).

## Референс Altech

`reference/altech/` — отобранный код рабочего дашборда другого проекта. Это **референс, не заготовка**:
у Altech одна воронка сделок, у нас две воронки с переходом «Компания → Сделка», два режима,
атрибуция менеджеров по истории и особые правила откатов.

Брать оттуда паттерны (атомарный стор, single-flight синк, race guard на фронте, стеклянный дизайн) —
да. Копировать бизнес-формулы и технические ID стадий Altech — нет.

Чего в Altech нет и что пишется с нуля: мультивыбор фильтров, произвольный диапазон дат,
часовой пояс портала, атрибуция менеджера по истории ответственных, переход между двумя воронками.
