# Дашборд воронки продаж — 3ДБИЛД

Веб-дашборд сквозной воронки продаж через две воронки Битрикс24 — «Компании» и «Сделки» —
с режимами Статики и Динамики, фильтрами, детализацией любой ступени и выгрузкой в XLSX.

Размещается на платформе «Битрикс24 Вайбкод» заказчика.

## Быстрый запуск

```bash
npm start
```

Открыть <http://localhost:3000>.

Зависимостей нет — `npm install` не нужен. Требуется Node.js 20 или новее.

При первом запуске снимок пуст, и приложение само наполняет его демонстрационными
данными: около 480 компаний и 430 сделок за 14 месяцев. Это не заглушки ради заглушек —
в наборе представлены все ситуации, на которых проверяются правила расчёта: компании
с несколькими потребностями, откаты в обеих воронках, отказы, пропущенные этапы,
передачи между менеджерами, записи без источника и без формата КЭВ.

## Проверки

```bash
npm test        # проверки бизнес-правил
npm run check   # синтаксическая проверка всех файлов
```

Проверки — обычные скрипты Node без тест-фреймворка. Каждая проверяет утверждение
о поведении системы, а не вызов функции: `откат компании не стирает достигнутые этапы`,
а не `тест функции buildFunnel`.

## Переключение на реальный Битрикс24

Скопировать `.env.example` в `.env` и заполнить. Значения вписываете вы — в репозиторий
они не попадают, `.env` перечислен в `.gitignore`.

```
DATA_SOURCE=bitrix
BITRIX_API_KEY=            # ключ доступа; в браузер не передаётся никогда
BITRIX_PORTAL_URL=         # адрес портала, нужен для ссылок на карточки
PORTAL_TIMEZONE=           # часовой пояс портала, например Europe/Moscow
```

Полный список того, что требуется получить от заказчика, — в
[ДАННЫЕ-ОТ-ЗАКАЗЧИКА.md](ДАННЫЕ-ОТ-ЗАКАЗЧИКА.md). Этот файл написан так, чтобы его
можно было переслать без правок.

Технические идентификаторы стадий обеих воронок до аудита портала заполнены заглушками
и собраны в одном месте — `src/domain/funnels.js`. Пока они не заменены, интерфейс
показывает предупреждение о неподтверждённой конфигурации.

## Устройство

```
Битрикс24 (источник истины)
      ↓ адаптер источника — реальный портал | генератор демо-данных
Нормализованный снимок (атомарный JSON-стор)
      ↓ расчётный модуль — ЕДИНСТВЕННОЕ место формул
HTTP API ──→ веб-интерфейс
        └──→ XLSX-выгрузка
```

| Каталог | Что внутри |
|---|---|
| `src/domain/` | Конфигурация двух воронок и работа с периодами. Ни одной формулы. |
| `src/analytics/` | Расчётный модуль. Всё, что считает числа, живёт здесь. |
| `src/api/` | Маршруты HTTP. Разбирают запрос, зовут расчёт, упаковывают ответ. |
| `src/sync/` | Синхронизация и адаптер источника данных. |
| `src/bitrix/` | Клиент реального портала. |
| `src/demo/` | Генератор демонстрационного снимка. |
| `src/export/` | Выгрузка XLSX. |
| `public/` | Интерфейс: ванильный JS без сборки. |
| `reference/` | Референс чужого проекта и исходная спецификация. Только чтение. |

Пользовательские запросы читают локальный снимок и не обращаются в Битрикс24 —
поэтому фильтры пересчитывают воронку мгновенно.

## Ключевые правила расчёта

Полный список — в [CONTEXT.md](CONTEXT.md). Три, которые определяют всё остальное:

**Правила откатов в двух воронках противоположны.** Откат компании не стирает
достигнутые этапы: используется исторический максимум. Откат активной сделки, наоборот,
убирает её со всех этапов выше текущего. Перепутать их — значит показать правдоподобные,
но неверные цифры, поэтому правило хранится в конфигурации воронки, а не в коде расчёта.

**Единица учёта меняется на стыке.** До ступени «Потребность выявлена» считаются
уникальные компании, после — уникальные сделки. Сама ступень несёт два счётчика
и читается как «Потребности выявлены — 189 (из 123 компаний)».

**Число ступени равно числу строк её детализации.** Не по совпадению, а по построению:
детализация не имеет собственного отбора и берёт те же множества, что и агрегат.

## Чего дашборд не делает

Осознанно, по спецификации: не показывает выручку, суммы и планы; не считает отказы
отдельным показателем; не строит прогнозов; не исправляет исторические данные CRM
и ничего не меняет в Битриксе — только читает.
