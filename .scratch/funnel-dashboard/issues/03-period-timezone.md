# 03 — Периоды и часовой пояс портала

**What to build:** Чистый модуль вычисления границ периода. Принимает тип периода и значение, возвращает границы в часовом поясе портала с обрезкой будущего. Единственное место в системе, где считаются даты.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

Читать до старта: `CONTEXT.md`, спека — раздел `Функциональные требования / Периоды`.
Референс: `reference/altech/src/analytics/dashboard.js`, блок периодов (`boundsForPeriod`, `clampPeriod`, `shiftPeriod`, `inPeriod`). **Важно:** в Altech всё жёстко UTC — это его известный дефект, здесь нужен настоящий часовой пояс портала.

- [ ] Поддержаны типы: `week`, `month`, `quarter`, `year`, произвольный диапазон `custom`, и режим `allHistory`.
- [ ] Дефолт — текущий календарный квартал.
- [ ] Границы считаются в часовом поясе портала из конфигурации, не в UTC. Часовой пояс — параметр, а не константа.
- [ ] Начальная и конечная даты произвольного диапазона включаются в расчёт полностью (от начала первого дня до конца последнего).
- [ ] Конец периода в будущем обрезается текущим моментом. При этом «естественный» конец периода сохраняется отдельным полем — он нужен для подписей, чтобы период не выглядел укороченным.
- [ ] `allHistory` не имеет нижней границы; верхняя — текущий момент.
- [ ] `inPeriod(date, period)` включителен с обеих сторон.
- [ ] Некорректный или неизвестный тип периода не роняет расчёт, а откатывается к кварталу.
- [ ] `scripts/check-period.mjs` — проверки: границы каждого типа периода; включительность краёв произвольного диапазона; обрезка будущего; сохранение естественного конца; корректность границ в поясе, отличном от UTC (в частности, что сутки не съезжают); переход через границу года и високосный февраль; `allHistory` без нижней границы.
- [ ] Все проверки детерминированы: текущий момент инъектируется параметром `now`, `new Date()` без аргументов в ожиданиях не встречается.
