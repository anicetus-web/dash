# 12 — Детализация ступени

**What to build:** Клик по любой ступени воронки открывает список конкретных сущностей, сформировавших её число, с переходом в карточку Битрикс24. Это инструмент доверия к цифрам: любое число можно разложить на строки.

**Blocked by:** 06

**Status:** ready-for-agent

Читать до старта: `CONTEXT.md` (инвариант 8), спека — раздел `Детализация`, приложение А6.
Референс: `reference/altech/public/app.js` — модалка и конфиг-объект срезов; `reference/altech/src/analytics/dashboard.js` — `sliceDeals`. **Дефекты доступности референса не переносить** (см. ниже).

**Главный инвариант:** детализация обязана вызывать ту же функцию, что и агрегат, а не повторять отбор. Число ступени и количество уникальных строк обязаны совпадать по построению, а не по совпадению.

- [ ] `getStageDetails(snapshot, request, stageId, page)` использует те же функции отбора, что и расчёт ступени.
- [ ] Количество уникальных строк совпадает с числом ступени. Общее количество считается **до** применения лимита, чтобы шапка списка была верной даже при усечении.
- [ ] Для компании показываются: технический ID, название, база/источник, менеджер, текущий этап, доступные даты переходов.
- [ ] Для сделки дополнительно: связанная компания и формат КЭВ.
- [ ] Тип сущности виден: до стыка строки описывают компании, после — сделки.
- [ ] Каждая строка ведёт на карточку Битрикс24; ссылка формируется на сервере из настроенного адреса портала, а не собирается в браузере.
- [ ] Повторные переходы одной сущности не создают повторных строк.
- [ ] Пагинация или явное указание усечения; при усечении видно, сколько строк показано из скольких.
- [ ] Запрос детализации использует тот же срез (режим, период, фильтры), что и открытая воронка.
- [ ] **Доступность (приложение А6):** модалка закрывается по Escape, удерживает фокус внутри, возвращает фокус на вызвавшую ступень при закрытии, имеет `role="dialog"` и `aria-modal="true"`. Ступени воронки активируются и мышью, и с клавиатуры.
- [ ] Гонки исключены: ответ устаревшего запроса детализации не подменяет содержимое открытого списка.
- [ ] `scripts/check-details.mjs` — проверки: **для каждой ступени обеих воронок** количество уникальных строк детализации равно числу ступени (это защита от расхождения слоёв, проверять по всем ступеням, а не выборочно); повторный переход не задвоил строку; общее количество считается до обрезки; неизвестная ступень даёт корректную ошибку, а не пустой список.
