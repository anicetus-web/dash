# 15 — XLSX-выгрузка текущего среза

**What to build:** Кнопка выгрузки отдаёт XLSX-файл с двумя листами: «Сводка» с параметрами среза и показателями и «Реестр» с обезличенным списком сущностей. Числа в файле совпадают с числами на экране при тех же параметрах.

**Blocked by:** 11, 12

**Status:** ready-for-agent

Читать до старта: спека — раздел `XLSX-выгрузка`, `Implementation Decisions` (последний пункт).

Зависимостей добавлять нельзя: XLSX — это ZIP с XML внутри, а `node:zlib` есть в стандартной библиотеке. Пишется свой минимальный генератор.

- [ ] Свой генератор XLSX без внешних зависимостей: корректный ZIP-контейнер поверх `node:zlib`, минимально необходимый набор частей документа, файл открывается в Excel и LibreOffice без предупреждений о повреждении.
- [ ] Экранирование XML: названия компаний с `&`, `<`, `"` и переводами строк не ломают файл.
- [ ] Числа записываются как числа, даты как даты — не как текст, иначе Excel не даст по ним считать.
- [ ] Лист «Сводка»: параметры среза (режим, период, применённые фильтры), дата формирования, дата последней синхронизации, ступени, количества и конверсии.
- [ ] Лист «Реестр»: технические ID, тип сущности, база/источник, менеджер, формат КЭВ, этапы, даты переходов, ссылки на Битрикс24.
- [ ] **Телефоны, email, комментарии и любые контактные данные в выгрузку не попадают.**
- [ ] Выгрузка строится поверх результата того же расчётного модуля — формулы не повторяются. Числа обязаны совпадать с интерфейсом при одинаковых параметрах.
- [ ] Выгрузка соответствует текущим фильтрам и режиму дашборда.
- [ ] Корректные заголовки ответа: тип содержимого XLSX и имя файла, отражающее срез и дату.
- [ ] `scripts/check-xlsx.mjs` — проверки: сгенерированный файл распаковывается как корректный ZIP и содержит ожидаемые части; спецсимволы в названиях экранированы; **числа в «Сводке» совпадают с результатом расчётного модуля для того же запроса** (главная проверка); количество строк «Реестра» согласовано с детализацией; контактные поля отсутствуют.
