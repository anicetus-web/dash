# 16 — Предупреждения качества данных, состояния и финальная полировка

**What to build:** Дашборд честно рассказывает о себе: где данные неполны, что устарело, что пусто, а что сломалось. Плюс финальный визуальный проход — экран должен выглядеть законченным продуктом, а не собранным прототипом.

**Blocked by:** 10, 11, 12, 13

**Status:** ready-for-agent

Читать до старта: спека — `Синхронизация и состояние системы`, `Детализация` пункт 34; `reference/altech/design/GLASS_DASHBOARD_HANDOFF.md` (раздел 10 — чек-лист приёмки).

- [ ] Предупреждения качества данных выводятся человеческим языком: записи без источника, сделки без формата КЭВ, отсутствующая история ответственных, неполная история стадий. Каждое предупреждение объясняет, на что оно влияет.
- [ ] Записи без источника видны отдельной категорией — это инструмент контроля качества CRM, а не мусор, который надо прятать.
- [ ] Три состояния строго различимы и по-разному оформлены: **загрузка**, **ошибка запроса или синхронизации**, **пустой результат фильтрации**. Пустой результат не выглядит как поломка.
- [ ] Устаревший снимок помечен явно, с датой последней успешной синхронизации.
- [ ] Ошибки показываются с понятной причиной и возможным действием, без технических трассировок в интерфейсе.
- [ ] Визуальная сверка с эталоном `reference/altech/design/glass-reference.html` по чек-листу приёмки handoff-документа: фон-градиент виден сквозь стекло, все панели стеклянные с акцентной линией под заголовком, заголовки и числа акцентным шрифтом, лейблы в верхнем регистре с трекингом, воронка с подсветкой и процентами.
- [ ] Числа выровнены по разрядам моноширинными цифрами — колонки воронки не должны «прыгать» при обновлении.
- [ ] Адаптив: на узких экранах ряды в одну колонку, сайдбар не ломает вёрстку. Горизонтальной прокрутки страницы нет ни на одной ширине.
- [ ] Уважается `prefers-reduced-motion`: анимации заполнения воронки и переходов отключаются.
- [ ] Фокус виден на всех интерактивных элементах; весь дашборд проходится с клавиатуры.
- [ ] `README.md`: что это, как запустить, как переключить демо-режим на реальный Битрикс, какие переменные окружения нужны (**имена, без значений**), где лежат спека и тикеты.
- [ ] `npm run check` и `npm test` проходят полностью.
