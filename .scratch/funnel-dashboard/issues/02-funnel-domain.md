# 02 — Доменная конфигурация двух воронок

**What to build:** Модуль, описывающий обе воронки как данные: этапы, порядок, единицу учёта, точку соединения. Вся остальная система спрашивает у него индексы и никогда не пишет ID стадий литералами.

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

Читать до старта: `CONTEXT.md` (разделы «Две воронки и точка соединения», «Инварианты расчёта»), спека — раздел `Funnel Definition`.
Референс: `reference/altech/src/domain/stages.js` — брать подход (явный `index`, Map по ID, алиасы, `capReachedIndexByCurrentStage`), не брать ID и порядок стадий Altech.

- [ ] Две конфигурации воронок: `companies` (6 этапов, единица учёта — компания) и `deals` (10 этапов, единица учёта — сделка), строго в порядке из спеки.
- [ ] У каждого этапа явный `index` — числом в конфиге, а не выводом из позиции в массиве.
- [ ] Ступень «Потребность выявлена» помечена как точка соединения: последняя в первой воронке и первая во второй, с признаком двойного счётчика.
- [ ] Технические ID стадий Битрикса вынесены в конфигурацию и заменяемы без правки кода — на момент разработки они неизвестны и будут получены аудитом портала.
- [ ] `canonicalStageId(id)` разрешает алиасы и применяется в каждой точке входа (событие истории, текущая стадия сущности, параметр среза).
- [ ] `stageIndex(funnel, stageId)` возвращает `-1` для неизвестных и служебных стадий (создана, отказ) — на этом инварианте держится вся математика воронки.
- [ ] `capReachedIndexByCurrentStage(funnel, reachedIndex, currentStageId)` ограничивает достигнутую глубину текущей стадией; при `currentIndex < 0` обрезки нет.
- [ ] Признак отказа сделки отделён от положительных этапов: отказ не является этапом воронки и не ломает индексацию.
- [ ] `scripts/check-domain.mjs` — проверки: порядок и уникальность индексов, разрешение алиасов, `-1` для неизвестной стадии, обрезка глубины при откате, отсутствие обрезки для стадии вне воронки, согласованность точки соединения между двумя воронками.
