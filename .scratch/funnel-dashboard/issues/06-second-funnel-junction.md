# 06 — Вторая воронка, точка соединения и правила откатов

**What to build:** Воронка на экране становится сквозной: компании сверху, ступень «Потребность выявлена» с двумя счётчиками посередине, сделки снизу. Правила откатов в двух воронках разные и работают именно так, как описано в спеке.

**Blocked by:** 05

**Status:** ready-for-agent

Читать до старта: `CONTEXT.md` (инварианты 1–6), спека — `Точка соединения`, `Режим Статики` пункты 5–9.

Ключевая сложность: **правила откатов в двух воронках противоположны.** В первой откат не стирает историю, во второй — стирает всё выше текущей стадии. Перепутать их значит показать заказчику неверные числа, которые выглядят правдоподобно.

- [ ] Каждая потребность — отдельная сделка. Одна компания с тремя потребностями даёт три сделки, считающиеся независимо.
- [ ] Ступень «Потребность выявлена» несёт два счётчика и отображается как `Потребности выявлены — 15 (из 10 компаний)`.
- [ ] До точки соединения единица учёта — уникальная компания, после — уникальная сделка. Переход единицы учёта виден в ответе API полем типа сущности у каждой ступени.
- [ ] Сделка не дублируется на этапе при повторном прохождении.
- [ ] **Активная сделка:** текущая стадия ограничивает верхнюю границу — после отката сделка исчезает с этапов выше текущего.
- [ ] **Повторное продвижение** после отката возвращает сделку на достигнутые этапы без дубля.
- [ ] **Проигранная сделка** сохраняет положительные этапы, достигнутые до отказа. Отказ не является этапом воронки; отказы и их причины отдельными показателями не выводятся.
- [ ] Компания без сделок корректно доходит до своей последней ступени первой воронки и не влияет на счётчики второй.
- [ ] Интерфейс визуально размечает стык: видно, где заканчиваются компании и начинаются сделки.
- [ ] `scripts/check-junction.mjs` — проверки: компания с несколькими потребностями даёт несколько сделок; сделка не дублируется при повторном входе; откат активной сделки убрал её с верхних этапов; повторное продвижение восстановило без дубля; проигранная сделка сохранила путь; откат компании и откат сделки обработаны **разными** правилами (проверить обоими случаями в одном тесте, чтобы правила нельзя было перепутать); два счётчика на стыке согласованы между собой.
